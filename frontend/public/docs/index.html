GETTING STARTED / 00

Sub2API API 快速开始

从控制台创建密钥，为密钥分配正确的平台分组，然后用当前站点的网关地址完成第一次请求。本文也给出常用开发工具的配置入口。

预计 5 分钟 适用于当前部署实例
01创建密钥在控制台生成凭证 02绑定分组确定平台和模型范围 03发送请求用模型 ID 验证链路 04检查用量确认额度和并发限制
01

创建 API 密钥

登录控制台后进入「API 密钥」，点击创建按钮。名称只用于区分用途，建议按客户端或环境命名，例如「Codex 开发」或「生产服务」。

  1. 1

    打开登录页，完成登录或注册。

  2. 2

    进入API 密钥，填写名称并设置需要的配额、有效期或 IP 规则。

  3. 3

    创建后立即保存完整密钥。后续示例统一使用环境变量 SUB2API_API_KEY。

!
密钥属于服务端凭证

不要写入浏览器代码、移动端包、公开仓库或文档截图。生产环境应通过环境变量或密钥管理服务注入。

02

选择与客户端匹配的分组

分组决定密钥可使用的平台、模型集合、调度池和计费规则。同一密钥应绑定到与你准备使用的协议相匹配的分组。

使用场景分组平台主要接口
Codex、OpenAI SDKOpenAI 或兼容分组/v1/responses
Claude Code、Anthropic SDKAnthropic 或兼容分组/v1/messages
Gemini CLI / SDKGemini 分组/v1beta
通用 OpenAI 客户端支持聊天补全的分组/v1/chat/completions
i
以控制台实际结果为准

管理员可以调整分组和模型范围。请求前先在模型广场或 GET /v1/models 中确认可用的精确模型 ID。

03

验证第一条请求

下面示例使用 OpenAI 兼容的聊天补全接口。把 YOUR_MODEL_ID 替换为当前分组内真实存在的模型 ID。

curl {{API_BASE_URL}}/chat/completions \
  -H "Authorization: Bearer $SUB2API_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "YOUR_MODEL_ID",
    "messages": [{"role": "user", "content": "你好"}],
    "stream": true
  }'
from openai import OpenAI

client = OpenAI(
    api_key="YOUR_API_KEY",
    base_url="{{API_BASE_URL}}",
)

response = client.chat.completions.create(
    model="YOUR_MODEL_ID",
    messages=[{"role": "user", "content": "你好"}],
)
print(response.choices[0].message.content)
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.SUB2API_API_KEY,
  baseURL: "{{API_BASE_URL}}",
});

const response = await client.chat.completions.create({
  model: "YOUR_MODEL_ID",
  messages: [{ role: "user", content: "你好" }],
});
console.log(response.choices[0].message.content);
HTTP200 OK

返回 JSON 或持续输出 SSE 事件，表示鉴权、分组和模型路由均已连通。

CORE CONCEPTS

身份认证

网关请求使用 Bearer Token。每个密钥独立记录额度、限流和使用日志，因此不同应用与环境应使用不同密钥。

HTTP Header Authorization: Bearer $SUB2API_API_KEY

Base URL 与常用端点

SDK 通常填写包含 /v1 的 Base URL；直接发送 HTTP 请求时，再追加具体资源路径。

BASE URLhttps://your-domain.example/v1
方法端点用途
POST/v1/responsesOpenAI Responses / Codex
POST/v1/chat/completionsOpenAI 兼容聊天补全
POST/v1/messagesAnthropic Messages
GET/v1/models查询密钥可见的模型

模型选择

模型名不是展示标题，而是请求体中的精确 model 值。模型范围会随分组配置变化，不建议把文档示例中的占位值直接写入生产代码。

01先查列表

通过模型广场或 GET /v1/models 获取当前密钥可见模型。

02再固定版本

确认能力与价格后，将精确模型 ID 写入应用配置并纳入变更管理。

流式响应

请求体设置 "stream": true 后，网关会持续转发上游事件。客户端应增量读取事件，并在用户取消或网络断开时主动终止请求，避免无效消耗。

客户端请求→网关鉴权与调度→SSE 增量事件→完成或取消

TOOLING

Codex 配置

为 Codex 创建独立 Provider，并通过环境变量提供密钥。模型 ID 请替换为 OpenAI 分组实际提供的模型。

~/.codex/config.toml
model_provider = "sub2api"
model = "YOUR_MODEL_ID"

[model_providers.sub2api]
name = "Sub2API"
base_url = "{{API_BASE_URL}}"
env_key = "SUB2API_API_KEY"
wire_api = "responses"
requires_openai_auth = false
supports_websockets = false
Terminal
export SUB2API_API_KEY="YOUR_API_KEY"
codex
i
配置更新后新建会话

完全退出并重新打开 Codex CLI、桌面端或编辑器扩展，让客户端重新加载 Provider 与工具配置。

Claude Code 配置

Claude Code 使用 Anthropic 兼容根地址。这里的地址不带 /v1，客户端会自行追加 Messages API 路径。

Terminal
export ANTHROPIC_BASE_URL="{{API_ROOT_URL}}"
export ANTHROPIC_AUTH_TOKEN="YOUR_API_KEY"
export CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1
export CLAUDE_CODE_ATTRIBUTION_HEADER=0

claude

如使用 Antigravity 专用分组，根地址通常需要追加 /antigravity。请以控制台「使用密钥」弹窗生成的配置为准。

OpenAI SDK

现有 OpenAI SDK 项目通常只需替换密钥和 Base URL。业务请求结构保持不变，模型名改为分组中存在的 ID。

Python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["SUB2API_API_KEY"],
    base_url="{{API_BASE_URL}}",
)

CC Switch

API 密钥列表提供「导入到 CC-Switch」操作。选择目标客户端后，控制台会把站点地址、平台类型和当前密钥写入导入链接。

  1. 1

    先安装 CC Switch，并确认系统已注册 ccswitch:// 协议。

  2. 2

    进入API 密钥，在目标密钥右侧点击「导入到 CC-Switch」。

  3. 3

    核对 Provider、平台和 Base URL，保存并启用配置。

  4. 4

    重启对应的命令行工具或编辑器。

TROUBLESHOOTING

常见错误

400请求参数不匹配

检查协议、模型 ID、请求体字段与所选分组能力。

401认证失败

检查密钥是否完整、有效，以及请求头是否使用 Bearer 格式。

403权限或访问规则拦截

检查密钥状态、IP 白名单、分组绑定和账户权限。

404端点不存在

确认 Base URL 没有重复或遗漏 /v1。

429达到限流或并发上限

降低并发，并按响应信息等待后重试。

5xx网关或上游暂时不可用

保留请求时间与错误内容，到使用日志中定位对应记录。

额度、并发与使用记录

密钥可以独立设置消费额度、时间窗口限流、并发限制、有效期和 IP 访问规则。排查调用失败时，先同时检查密钥页与使用记录。
